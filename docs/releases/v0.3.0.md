# Delay Reporter v0.3.0

A standalone Windows tool that reads a movement sheet, extracts the coded departure delays, and
writes a professional, printable Excel workbook ready for the station's own notes.

## What's new since v0.2.0

- **MX classification.** Delay codes carry an additional `category` column, seeded `MX` for every
  code in the 40s. The summary reports "with MX coded delay", and each reported flight carries a
  tick in the preview — Automatic, Force, Exclude — to correct that classification for the file
  currently open. The tick is never saved and resets when you open another file.
- **Operator names, checked against a real file.** The OPR column shows the resolved carrier name by
  default. `operators.csv` grew from 8 to 13 entries: AeroLogic, EAT Leipzig, 21 Air, Kalitta
  Charters II and Singapore Airlines were added after checking a real CVG movement sheet's operator
  codes against the mapper and verifying each match independently, rather than guessing. One code
  the sheet carries (`WIN`) could not be confirmed and stays unmapped.
- **Aircraft label format.** A view option for how much of a mapped label shows: the model family
  alone (`767`), family and variant (`767-300`), or the full label as written in `aircraft-types.csv`.
- **A Settings dialog.** The aircraft and operator choices above, plus how the preview's Codes
  column treats a code the Delay codes filter did not choose — visible, dimmed, or left out
  entirely (preview only; the saved workbook always lists every code, so its coded total keeps
  reconciling with the clock delay). All four choices persist across restarts.
- **A shorter default summary.** Closing the exclusion-accounting gap in 0.2.0 grew the summary to
  nineteen line items, which read like a debug log. It's now seven: station departures, no coded
  delay, with coded delay, with MX coded delay, below threshold, flights reported, delay events.
  Nothing was actually dropped — a **Show additional debug data** setting appends one line, on
  screen and in the workbook, carrying every exclusion, mapping and reconciliation count the
  default leaves out.
- **Printing fix.** Only the table header row repeats on pages after the first; the title, subtitle
  and summary now belong to page one alone, rather than reprinting the whole (now much longer)
  block on every page.

## What it does

- Opens movement sheets as `.xlsx` or `.csv`, by dialog, command line, or by dropping the file on
  the window. The header row is found by column name, so title rows above the table, extra columns
  and reordered exports all read. Shared and inline strings are both handled.
- Unpacks the `Dep delay` column — N reason codes followed by N durations, such as
  `93A/09/28A/00:17/00:15/00:10` — into individual coded delays, paired in order.
- Names every delay code from an editable list seeded with all 173 codes of *Global Network Delay
  Codes v8.1*, matching the sheet's zero-padded `09` to the list's `9`, and resolves aircraft types
  and operators the same way. Delay codes also carry a cause category, starting with MX.
- Reports only this station's departures: `From` is the station and `To` is not, so arrivals,
  ground runs and tows are excluded and counted. The station is a setting, and the application says
  so when the file is mostly about a different one.
- Filters by station, movement type, date range, operator, delay code and tail number, each a
  dropdown built from the file, with a minimum-delay threshold measured against either the included
  codes or the actual clock delay.
- Measures the real delay from STD to ATD, carrying a departure past midnight forward rather than
  reporting a negative delay, and flags in red any flight whose codes do not add up to it.
- Pre-fills each flight's Notes cell with the supplementary information its codes oblige, and
  counts how many flights still owe it.
- Writes one sheet: a compact summary that repeats only its table header when printed, then one row
  per flight with its codes stacked and aligned inside that row, a blank Notes column, an
  autofilter, a frozen header and landscape fit-to-width print setup.
- Shows a live preview of exactly what will be written, and a Preview in Excel button to see the
  real workbook without saving it.

## Running it

Download `DelayReporter.exe` and run it. No installer, no runtime to install, no companion DLL, and
no administrator rights: it writes only to `%APPDATA%\Delay Reporter\`, to a temporary file for
Preview in Excel, and to the file you choose to save. The executable is unsigned, so a downloaded
copy may trigger a Windows security prompt.

On first run it writes three editable CSVs to `%APPDATA%\Delay Reporter\mappings\` and never
overwrites them again. `delay-codes.csv` controls how codes are named, which are excluded from
reporting, what supplementary information each one demands, and its cause category. `aircraft-types.csv`
maps IATA equipment codes to readable names. `operators.csv` maps ICAO-style operator codes to a
carrier name. Help > Mappings opens the folder.

Nothing is excluded by default: the first report shows everything, so you can decide what your
station does not own.

## Known limits

- Departure delays only. The `Arr delay` column has the same structure and is not parsed; the model
  has room for it.
- The mapping seeds are a starting point, not a claim about your own station's fleet or operator
  list, and should be checked before the first report goes out. One real operator code seen at CVG
  (`WIN`) could not be confidently identified and ships unmapped.
- The delay code labels are transcribed verbatim from v8.1, including that document's own spelling
  and a handful of inconsistent field values. Local corrections belong in your own copy of the file.
- Validated against one week of real movements at one hub, plus a synthetic fixture. A station
  whose export differs structurally may need the format notes revisiting.

## Validation

Release build with no warnings. Core regression checks covering delay-cell parsing and its failure
modes, midnight-crossing delay arithmetic, code normalisation, mapping load and exclusion, station
and movement-type filtering, report figures, workbook structure and print setup. Repository checks
covering version agreement across the project file, manifest, README, changelog and release notes,
mapping seed integrity, and the absence of binaries or real operational data.

Every setting introduced in this release was exercised against the demo sample and confirmed live:
the MX tick cycling the summary's count up and down, the Settings dialog's operator and aircraft
choices changing the actual generated workbook, and delay-code dimming rendering correctly in the
preview. The updated `operators.csv` was checked against a real, non-synthetic CVG movement sheet
(not committed to this repository) and resolves ten of its eleven distinct operator codes.

The repository contains no real movement data. Licensed under the MIT licence.
