# Delay Reporter v0.4.0

A feature release: the window is redesigned to match ICS Scrubber and OFT Scrubber, the workbook
gains a new default layout modelled on printed movement delay reports, and the report gains
selection, search, presets and a compact email draft.

## What's new since v0.3.1

- **A redesigned window**, matching the family's shared `Fluent.xaml` and `Shell.xaml` theme: a
  File menu, Home, Presets, View and Help ribbon tabs, a collapsible options pane, and a status bar
  whose standing text is the report's summary. Every column heading carries a sort tag and, where
  it applies, a filter tag, both quiet until they matter.
- **A grouped workbook layout**, the new default: black on white, no boxes or bands, tall rows
  centred vertically, flights in groups of five under a thin rule, and an empty Notes column to
  write in — a mismatched delay still shows both figures, `0:32 ≠ 0:25`, so it reads on a black and
  white printout. The **Classic** layout is kept behind a setting, unchanged, for comparison and
  rollback.
- **Row selection, hiding and partial reporting.** Rows can be selected, hidden (and unhidden), and
  a report can be saved, previewed or emailed from only the selected flights — every flight left out
  this way is counted on the summary, never dropped silently.
- **An MX filter** (all flights, MX only, not MX) alongside the existing minimum-delay and station
  filters, and a plain on/off MX tick per flight in the preview to correct the mapping's
  classification for the file currently open.
- **A search bar** over the flight list that looks through every field of every flight and narrows
  the report exactly like any other filter; what it excludes is counted on the summary.
- **Presets**: three built in (Standard, Every coded delay, Over an hour) plus your own, saved under
  `%APPDATA%\Delay Reporter\presets\`. None of the built-in presets restrict movement types,
  operators, delay codes or tail numbers by default — narrowing any of them is a deliberate choice,
  not a hidden default.
- **A compact email draft.** Send email writes the report as an unsent `.eml` and opens it in the
  default mail app, with the workbook attached by default. The table is drawn in a new
  monochrome "Ink Minimal" style — a bold rule under the header, no zebra striping, generous row
  padding, and each flight's delay codes given space of their own rather than a tight list — and
  now shows the OPR and From columns alongside Reg, To, STD, ATD, Delay and Codes. The Outstanding
  column is left out of the email table for now; the plain-text draft still lists what each flight
  owes, and the workbook's own hints are unaffected.
- **New defaults for a freshly opened file.** Movement types and tail numbers start with everything
  ticked (no restriction); operators start ticked to the station's own default carriers (`S3`,
  `CJT`, `CKS`, `CSB`, `DHK`, `KII`, `SIA`), falling back to no restriction when a file holds none
  of them. The Date column defaults to `dd MMM yyyy` (`23 Sep 2026`) instead of printing as
  written in the file.
- **A Settings dialog**, laid out like Outlook's: workbook layout, the OPR column's carrier names,
  date format, aircraft label format, how the preview treats codes the Delay codes filter did not
  choose, email recipients and attachment, and a debug summary line. Mappings and settings folders
  move off the Home tab into Help > Data folder and a new Data page in Settings.

## What it does

Everything in [v0.3.0](v0.3.0.md) plus the above: reads a movement sheet as `.xlsx` or `.csv`,
unpacks its coded departure delays, resolves each code, aircraft type and operator against an
editable mapping file that always wins over the seed, and writes a printable Excel workbook (or a
compact email) of exactly the flights the list shows — never more, never silently fewer.

## Running it

Same as v0.3.1: download `DelayReporter.exe` and run it. No installer, no runtime to install, no
administrator rights. `%APPDATA%\Delay Reporter\settings.txt` now also remembers the options pane
and summary's shown state, alongside the station, minimum delay and every Settings page.

## Validation

Release build with no warnings. Core regression checks and repository checks both pass, including
the reworked filter defaults and the redrawn email draft's HTML and plain-text output. The window
itself — the options pane, row selection and hiding, search, presets and the email draft as Outlook
renders it — has not yet been exercised live against a real movement sheet; do that before this
release goes out.
