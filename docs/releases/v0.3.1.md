# Delay Reporter v0.3.1

A patch release. No behaviour changed except one mapping correction; see
[v0.3.0](v0.3.0.md) for what the current feature set does.

## Fixed

- `operators.csv`: `WIN` is **Awesome Cargo**, confirmed by the station. It shipped unmapped in
  v0.3.0 because a web search misidentified it and no independent source confirmed the real answer
  in time — guessing was rejected in favour of an honest "unmapped" tag over a wrong carrier name
  in an operational report. All eleven distinct operator codes seen in the CVG file used to check
  this release now resolve.

## Documentation

- README gained a standalone "Rebuilding the executable" section stating the exact build command
  and output path, separate from the fuller build-and-verify flow.

## Running it

Same as v0.3.0: download `DelayReporter.exe` and run it. No installer, no runtime to install, no
administrator rights. `%APPDATA%\Delay Reporter\mappings\operators.csv` is written once and never
overwritten, so an existing installation keeps its own edits — this fix reaches only fresh installs
or a station that deletes its copy to pick up the new seed.

## Validation

Release build with no warnings. Core regression checks and repository checks both pass. The
updated `operators.csv` was re-checked against the same real, non-synthetic CVG movement sheet used
for v0.3.0 (not committed to this repository) and now resolves all eleven of its distinct operator
codes, up from ten.

The repository contains no real movement data. Licensed under the MIT licence.
