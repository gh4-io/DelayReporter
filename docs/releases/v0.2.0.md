# Delay Reporter v0.2.0

A standalone Windows tool that reads a movement sheet, extracts the coded departure delays, and
writes a professional, printable Excel workbook ready for the station's own notes.

## What's new since v0.1.0

- **Every excluded row is now counted.** Rows rejected by the station-departure test — arrivals,
  other stations, and ground runs or tows at the report's own station — used to be dropped with
  nothing on the summary to explain them. A single `Excluded by filters` counter also covered four
  unrelated reasons (date, operator, tail number, delay code) at once. Every drop point now has its
  own counter, so the summary's rows-read figure reconciles exactly against everything reported and
  everything excluded, closing the last gap in the project's "nothing disappears silently" promise.
- **Operators are resolved, not just filtered.** A new editable `operators.csv`, following the exact
  pattern already used for delay codes and aircraft types, maps the `OPR` column's ICAO-style codes
  to a carrier name. It ships seeded with a handful of well known cargo carriers as a starting point;
  an operator absent from the file is never fatal and is listed on the summary, the same as an
  unmapped code or aircraft type.
- **Filters are dropdowns, not free text.** Station is now an editable, single-select dropdown filled
  with the stations seen in the loaded file. Movement type, operator, delay code and tail number are
  a new multi-select dropdown built from the values actually present in the file, showing the mapped
  label beside operator and delay codes once one exists. Ticking nothing and ticking everything both
  mean no restriction, matching the filtering behaviour from v0.1.0 exactly — only how you set it up
  has changed.
- **Preview in Excel.** A new button next to Generate report writes the current report to a temporary
  file and opens it in Excel immediately: no save dialog, no prompt. Generate report is unchanged and
  remains the way to keep a copy.

## What it does

- Opens movement sheets as `.xlsx` or `.csv`, by dialog, command line, or by dropping the file on
  the window. The header row is found by column name, so title rows above the table, extra columns
  and reordered exports all read. Shared and inline strings are both handled.
- Unpacks the `Dep delay` column — N reason codes followed by N durations, such as
  `93A/09/28A/00:17/00:15/00:10` — into individual coded delays, paired in order.
- Names every delay code from an editable list seeded with all 173 codes of *Global Network Delay
  Codes v8.1*, matching the sheet's zero-padded `09` to the list's `9`, and resolves aircraft types
  and operators the same way.
- Reports only this station's departures: `From` is the station and `To` is not, so arrivals,
  ground runs and tows are excluded and counted. The station is a setting, and the application says
  so when the file is mostly about a different one.
- Filters by station, movement type, date range, operator, delay code and tail number, each a
  dropdown built from the file, with a minimum-delay threshold measured against either the included
  codes or the actual clock delay.
- Measures the real delay from STD to ATD, carrying a departure past midnight forward rather than
  reporting a negative delay, and flags in red any flight whose codes do not add up to it.
- Pre-fills each flight's Notes cell with the supplementary information its codes oblige, and
  counts how many flights still owe it.
- Writes one sheet: a summary block that repeats when printed, then one row per flight with its
  codes stacked and aligned inside that row, a blank Notes column, an autofilter, a frozen header
  and landscape fit-to-width print setup.
- Shows a live preview of exactly what will be written, and a Preview in Excel button to see the
  real workbook without saving it.

## Running it

Download `DelayReporter.exe` and run it. No installer, no runtime to install, no companion DLL, and
no administrator rights: it writes only to `%APPDATA%\Delay Reporter\`, to a temporary file for
Preview in Excel, and to the file you choose to save. The executable is unsigned, so a downloaded
copy may trigger a Windows security prompt.

On first run it writes three editable CSVs to `%APPDATA%\Delay Reporter\mappings\` and never
overwrites them again. `delay-codes.csv` controls how codes are named, which are excluded from
reporting, and what supplementary information each one demands. `aircraft-types.csv` maps IATA
equipment codes to readable names. `operators.csv` maps ICAO-style operator codes to a carrier name.
Help > Mappings opens the folder.

Nothing is excluded by default: the first report shows everything, so you can decide what your
station does not own.

## Known limits

- Departure delays only. The `Arr delay` column has the same structure and is not parsed; the model
  has room for it.
- Aircraft type names are seeded from standard IATA equipment codes for the thirteen types present
  in the development sample, and operator names are seeded for a handful of well known cargo
  carriers. Both are a starting point, not a claim about your own station's fleet or operator list,
  and should be checked before the first report goes out.
- The delay code labels are transcribed verbatim from v8.1, including that document's own spelling
  and a handful of inconsistent field values. Local corrections belong in your own copy of the file.
- Validated against one week of real movements at one hub, plus a synthetic fixture. A station
  whose export differs structurally may need the format notes revisiting.

## Validation

Release build with no warnings. Core regression checks covering delay-cell parsing and its failure
modes, midnight-crossing delay arithmetic, code normalisation, mapping load and exclusion, station
and movement-type filtering, report figures, workbook structure and print setup. Repository checks
covering version agreement across the project file, manifest, README, changelog and release notes,
mapping seed integrity, and the absence of binaries or real operational data.

Against the synthetic sample, the summary's rows-read figure now reconciles exactly: every one of
the 15 rows is either a reported flight or accounted for by exactly one exclusion counter. Preview
in Excel was exercised against a live Excel installation and opens the temporary workbook with no
prompt.
